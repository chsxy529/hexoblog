## 🚀 AI 前沿速递 (2026-06-02)

**1. Anthropic 提交 IPO 保密申请，估值近万亿美元**

Anthropic 于 6 月 1 日秘密向 SEC 提交了 Form S-1 文件，正式启动 IPO 流程。在 5 月底的 $650 亿融资轮中，Anthropic 以约 9650 亿美元估值超越 OpenAI，成为有史以来估值最高的初创公司。同日发布，Anthropic 将网络安全 AI 模型 Mythos（Project Glasswing 项目）扩展至全球 15 个国家的约 150 家组织，包括欧盟网络安全局和印度等国。

- 💡 *博主锐评：万亿估值 IPO 意味着资本市场已经把 Anthropic 当作"必赢牌"，但 S-1 文件的公开内容一旦披露，财务健康度（烧钱率、营收/估值比）将面临严苛审视。Mythos 模型限流分发而非开源，本质是把安全能力变成准垄断基础设施——这既是护城河，也是监管靶子。*

**2. 特朗普签署缩减版 AI 行政令，30 天发布前审查**

特朗普于 6 月 2 日签署了一份缩减版行政令，要求 AI 公司在发布前 30 天（原草案 90 天）自愿提交新模型供政府评估。行政令不包含强制性政府许可或前置审批。此前草案因行业强烈反对（包括前白宫 AI 沙皇 David Sacks 游说）而推迟。行政令还要求国防部 30 天内加强网络安全、司法部将 AI 辅助黑客列为重点执法方向。

- 💡 *博主锐评：从 90 天压缩到 30 天、从强制到"自愿"，行政令实质是象征性表态。真正值得注意的是"AI 辅助黑客行为列为重点执法方向"——这等于变相告诉业界：攻击性 AI 工具正在进入联邦检察官的武器库，合规部门需要准备新的红线扫描。*

**3. OpenAI Codex 周活突破 500 万，推出知识工作者新工具**

OpenAI 宣布 Codex 周活跃用户已超过 500 万，自 2 月桌面应用发布以来增长 6 倍以上。非开发者知识工作者现占总用户 20%，且增长速度快于开发者 3 倍。同步推出面向企业办公场景的新工具套件，包括 Sites（可部署轻量级 Web 应用）、Annotations 等。OpenAI 发布内部报告"知识工作新纪元"，展示数据分析、研究、知识文档等场景快速增长。

- 💡 *博主锐评：知识工作者占比 20% 但增速是开发者的 3 倍——这意味着"编码智能体"的故事快讲完了，下一个增量市场在"非编码知识工作"。但 Sites 和 Annotations 本质上是拼贴功能，不是差异化壁垒，OpenAI 真正要验证的是企业是否愿意为 Codex 订阅重复付费。*

**4. 微软 Build 发布 Scout AI 个人助手，基于 OpenClaw 框架**

微软在 Build 大会上发布了 Scout——一款基于 OpenClaw 框架构建的"常驻型"AI 个人助手，内置 Microsoft 365 生态，可学习用户工作习惯、管理日历、起草会议纪要。提供"政策合规系统"和审计追踪功能，通过 Microsoft Frontier 计划面向早期用户开放，需 GitHub Copilot 订阅。

- 💡 *博主锐评：Scout 的本质是把 Copilot 从"工具"升级为"代理人"，但 OpenClaw 框架的开源定位与 Scout 的企业锁定策略之间存在天然张力。更关键的是——审计追踪在 AI 时代不是技术问题，是法律问题：当 AI 替你发邮件、替你答应客户需求，责任链怎么切割？*

**5. 马丁·斯科塞斯加入 AI 图像生成公司 Black Forest Labs（FLUX 开发商）**

著名导演马丁·斯科塞斯加入 AI 图像生成公司 Black Forest Labs 作为顾问，使用 FLUX 工具进行电影前期故事板创作。这是好莱坞顶级导演首次公开为 AI 工具背书，标志电影行业对 AI 态度从"抵制"转向"有限接受"。Black Forest Labs 此前曾拒绝 Elon Musk 旗下 xAI 的合作邀请。

- 💡 *博主锐评：用 AI 做故事板≠用 AI 做最终成片。好莱坞分两步走：先用 AI 降低前期成本，后期再靠工会保护"真实拍摄"溢价。斯科塞斯的背书是信号弹——FLUX 这类模型在前期制作环节已经够用，但真正改变行业结构的是后期制作管线。*

**6. 数学家发布《莱登声明》，警告 AI 对数学研究的威胁**

国际数学联合会 endorse 了《莱登声明》，警告 AI 可能产生"看似合理但不可靠甚至错误的论证"，威胁数学研究的正确性、透明度和可验证性。声明指出 AI 模型大量使用未正确标注来源的已发表论文进行训练，可能扰乱学术界的雇佣、资助和认可机制。

- 💡 *博主锐评：数学是最不可能被 AI "替代"的领域之一，因为数学的核心不是模式识别而是严格证明。但 AI 生成的"看似合理"的推导正在污染 peer review 体系——当审稿人自己也被 AI 训练过，辨别能力本身就在退化。*

## 🌟 今日开源明星：anomalyco/opencode

> GitHub: [anomalyco/opencode](https://github.com/anomalyco/opencode) | ⭐ 55,282 stars（近 28 天 +970，增长最快）| TypeScript

### 1. 为什么推荐它？

opencode 是近期增长最快的终端原生 AI 编码工具，28 天新增近 1000 星，增速远超 Claude Code 和 Cursor。它的核心定位是"轻量级、快速迭代的终端 AI 编程环境"——没有 GUI 的臃肿，没有 IDE 的延迟，直接在终端中完成代码编辑、调试和项目管理。对于习惯终端工作流的开发者来说，opencode 提供了比 Cursor 更轻量、比 Claude Code 更开放的选择。

### 2. 核心特性与技术栈

| 特性 | 说明 |
|------|------|
| 终端原生 | 无需 GUI，全程 CLI 操作 |
| LLM 后端可切换 | 支持 OpenAI、Anthropic、本地模型 |
| 上下文感知 | 自动感知项目结构和依赖 |
| 快速迭代 | 低延迟，适合频繁编辑 |

```
┌─────────────────────────────────────────────┐
│              Terminal UI                     │
│  ┌───────────────────────────────────────┐  │
│  │  opencode> 编辑 main.rs               │  │
│  │  🤖 LLM: 已优化 3 处性能瓶颈         │  │
│  │  opencode> 应用更改? [Y/n]           │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

### 3. 实战：本地部署与使用指南

```bash
# 克隆仓库
git clone https://github.com/anomalyco/opencode.git
cd opencode

# 安装依赖
npm install

# 配置 API Key
export ANTHROPIC_API_KEY=sk-ant-...
# 或 export OPENAI_API_KEY=sk-...

# 启动
npm run start
```

### 5. 适用场景

- ✅ **终端重度用户**：vim/neovim 党，不需要 GUI 的开发者
- ✅ **快速原型验证**：需要快速编辑和测试代码片段的场景
- ⚠️ **大型代码库**：目前上下文窗口限制对超大项目不太友好
- ❌ **新手开发者**：需要 GUI 引导和更友好的错误提示
